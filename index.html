01 · THE ASSET LAYER

把一句口语，炼成一条资产

成片质量的上限，取决于卖点资产的质量。这一层做的事：把一句口语，变成一个能被统计、能跨期对比、能被下游调用的标准条目。

素材原话 “还是不含白砂糖和脂的”
→
① 抽取 不含白砂糖
→
② 归一 无蔗糖
→
③ 归类 糖分与碳水控制
→
④ 挂骨架 健康功能

一句口语 → 标准卖点词 → 挂进「二级卖点 → 一级卖点」的稳定骨架。这层资产，是后面一切的地基。

02 · WHY MULTI-AGENT

同一件事，三种互相冲突的判据

上面四步看着简单，但每一步对「什么叫做得好」的要求，是互相打架的。

CRITERION Ⅰ · 抽取

要忠于原文

一个字都不能改

「不含白砂糖」必须原样保留——改了就不再是素材里真实说过的话，证据链就此断裂。

CRITERION Ⅱ · 归一

要敢改写

必须改写成标准词

只有改写成「无蔗糖」，才能和「零蔗糖」「不加一点糖」合并成同一个标准条目。

CRITERION Ⅲ · 归类

要看全局

必须知道整个行业

得掌握整个子行业的类目全貌，才能把「无蔗糖」和「低糖」「控糖」放到正确的位置。

单 Agent 方案的实测失败样本：129 对纯语序倒装重复（「无蔗糖粗粮」≈「粗粮无蔗糖」）无法识别；「拍二发三」「平台补贴」等价格词被误收为卖点，甚至单独成簇 4 个——判据在同一上下文中互相污染，拆分成为必然。

三套判据塞进同一个上下文，必然互相污染——于是拆开，让每个 Agent 只守一条判据。

03 · ARCHITECTURE

一个调度，五个单元

Orchestrator 是整个系统的唯一入口，但它自己一个卖点都不抽——只做意图识别、分派、校验与收口。

ORCHESTRATOR

调度器

串行分派、逐步校验、收口写库——不抽词、不聚类、不路由，不触碰任何业务判断。

意图识别分派产物校验失败分类处置断点续跑扩框架判定人工确认
01 · EXTRACTOR

抽取 Agent

逐条从口播里切出卖点段，每条带原文证据可溯源。无状态设计：切成 100 条一片，fan-out 多实例并行抽取再 merge 装配——全系统唯一的并行点。

02 · FRAMEWORK BUILDER

框架构建 Agent

把卖点词组织成「二级簇 → 一级骨架」。内部再调度两个 worker 分步加工，自判一级映射、全局二次审查后才冻结：

02a · 规整同义合并、标准化命名
02b · 聚类归成 25–35 个二级簇
03 · ROUTER

路由 Agent

期次更新的日常主力。检索优先、LLM 兜底：cos ≥ 0.9 自动归属再复查，0.5–0.9 复核 topk，低于 0.5 全库复核。只用框架、绝不改框架——装不下的交回 02。

04

库治理 · 确定性脚本

全系统唯一写库入口，且不是 LLM。发 ID、写累积 / 当期双口径、留变更日志与入库前快照，幂等可重跑。

05

评测 Agent · 独立第三方

与生产链路平级，不读取执行侧任何自述理由，按四模块逐条独立判分——生产与评测彻底隔离。

6 个角色2 种运行模式每步契约化交接每步硬校验唯一并行点

每个 Agent 的上下文里只有自己那一份技能书——判据互不串味。

04 · DESIGN PRINCIPLES

从失败中沉淀的三条设计原则

不是框架选型问题，而是踩过坑之后守住的边界——它们贯穿了上面整张架构图。

PRINCIPLE Ⅰ

判断归 LLM，确定性归脚本

能算出来的，绝不让模型猜

切片、合并、相似度召回、发 ID、写库、校验，全部是确定性脚本。模型只做它真正擅长的事：语义判断。

PRINCIPLE Ⅱ

默认串行，逐步校验

任何一步不过，流水线停在原地

每步产物落盘、契约化交接，上一步的输出就是下一步的输入，校验不过绝不向下传递——错误不扩散。

PRINCIPLE Ⅲ

权力分离

生产、写入、评测三权分立

调度器不做业务判断；写库只有一个入口；评测方不读被评方的自述理由。

06 · ENGINEERING

让 LLM 流水线工程级可信

模型输出天然存在抖动。可信不是靠运气，而是靠一圈确定性的工程机制兜出来的。

MECH · 01

失败先分类，再决定动不动

进程崩溃原样重试（至多 2 次）；质量不达标带反馈重跑（至多 1 次）；结构断链直接停止——因为重试不会变好。重试粒度压到最小：只重跑那一片、那一个单元。

进程类 ≤2 · 质量类 ≤1 · 结构类 stop
MECH · 02

每一步都有硬校验

计数不变式守住「不丢词」，簇数区间守住「粒度不漂」，落表前 UNMAPPED 必须为零。校验不过即停止并报告，错误绝不向下游传递。

covered + dropped ≡ total
MECH · 03

交接卡 + 台账，崩了接着跑

每步产出一份自洽 handoff（输入即上游输出），另有 run_state 台账记录每步状态。会话中断、进程崩溃，均可从断点续跑，已完成步骤不重跑。

handoff chain · run_state resume
MECH · 04

人在回路，全程可对账

凡涉及框架变更的新增条目，逐项经人工确认后方可入库；检索分流的原始快照只读封存，LLM 每一次改判均可对照快照审计——谁改的、改成什么，一目了然。

human-in-the-loop · audit baseline
MECH · 05 · 稳定性的来源

双通道向量化 + 连通块：归一不靠模型临场发挥

全量词先两两计算双通道相似度：Embedding 管语义，负责召回同义候选；TF-IDF 管字面，专门纠偏语义的「高分陷阱」——语义相近但字面相反的词对，不会被误并。达标的词对连成边，交给连通块算法确定性归并；LLM 只负责块内命名与裁决，不再每次重新「想」哪些词是一伙的。

cos = 0.7 × Embedding ＋ 0.3 × TF-IDF
双通道打分→连通块归并→LLM 块内命名

语义通道防「该并的漏了」，字面通道防「该拆的并了」——分组由图算法算出来，不靠模型临场想：三次独立运行，字面一致率 0.33~0.42 → 0.85~0.88。

07 · TEXTGRAD · SELF-IMPROVING PROMPTS

把 Prompt 调优，从手艺变成工程

引入斯坦福提出的 TextGrad（文本梯度）框架——把 LLM 对结果的批评当作梯度，反传回 Prompt 本身。人工调优的四个老大难：靠猜、说不清、不敢动、查不了，就此变成可归因、可判分、可门控、可追溯的自动闭环。
